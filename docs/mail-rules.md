# 邮件分类与回复建议规则

新邮件都保留摘要，并分为：通知邮件、会议邀请、账单与交易、账号与安全、推广与订阅、沟通与工作请求、其他邮件。分类不直接决定是否需要回复。

通知、日历邀请及提醒、账单收据、验证码、推广订阅默认只摘要和列出必要待办，不显示“要帮你拟回复吗”或回复命令。查看、付款、到官网处理、在日历接受或拒绝邀请都不等于需要邮件回复。

只有邮件提供具体依据时才推荐回复：明确要求邮件答复；需要协商时间或事项；存在具体错误、争议或拒绝结果且确有申诉/异议需要；必须询问缺失信息才能继续处理。推荐时同时展示依据。不凭空推测用户不满，不因收到处理结果就建议申诉。渠道只支持官网或客服处理时列出相应待办，不推荐回复自动通知地址。

例如：普通会议邀请不推荐回复；“请邮件确认周二是否方便”可以推荐。付款收据不推荐；有明确重复扣款证据且提供可回复客服渠道时，可以建议提出异议。账号异常提醒列出核实待办，不向自动安全邮件回复。

规则由 `src/mail-policy.js` 提供给模型；结构化结果保存分类、回复理由和依据。无有效理由或依据时，代码关闭回复推荐。语义分类和证据判断仍依赖模型，并非逐字确定的过滤器。

用户仍可通过“邮件回复 编号 你的意思”主动要求拟稿。推荐本身不生成草稿、不发送；发送仍要求用户明确确认展示的当前草稿版本。规则用于之后新分析的邮件，不自动改写已有摘要和排队通知。
