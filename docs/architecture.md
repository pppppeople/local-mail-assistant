# 架构和数据边界

摘要分类与回复建议遵循 [邮件规则](mail-rules.md)。模型输出分类、回复理由和依据；没有有效理由和依据的摘要不展示回复推荐。拟稿与确认发送仍为独立的本人操作。

常规摘要先存入 `digest_items`，到上海时间 9:00 / 18:00 的扫描轮次再原子转成通知队列；需要回复、紧急邮件和工作沟通待办直接排队。可选网页在同一邮件进程内监听 loopback，通过独立访问码和会话验证本人；网页和通知入口共用版本化草稿，不存在第二套发送状态。公开副本不提供远程访问部署；见 [README](../README.md)。

## 持久化与重试

每个邮箱的游标与新邮件插入在同一 SQLite 事务完成。IMAP 使用 UIDVALIDITY+UID，
Graph 保存 opaque nextLink/deltaLink，首跑基线分页完成前不推历史。
所有账户分开存储；通知每块保存稳定 client ID，仅重试未完成块。
传输属于至少一次交付：服务器已经接受而本地回执丢失时，是否按 client ID 去重
仍取决于微信服务，不承诺精确一次到达。连接错误不被当作成功发送。

扫描租约防止两个扫描进程同时消费；扫描期间续租。收信和摘要失败不会丢游标
之前已经存入的新邮件。对外邮件发送单独用草稿版本的原子状态更新抢占；
只有 review → sending 成功的那次确认可以调用传输。sent、sending 和 unknown
都不允许重复发送。进程在 sending 阶段退出后，该状态保留为待核实；不自动解锁。

## 私人边界

邮箱地址、正文、草稿、OAuth 令牌、授权码和数据库只在私人运行目录。
微信发送适配器须由用户另行提供，并显式指定路径；它负责自己管理的本人绑定、context 和 lease。公开副本不包含私人桥，也不会自动发现兄弟目录。
邮件项目通过 stdin 传入文本与稳定 client ID，不能传任意接收者。
通知和操作结果不写微信普通聊天记录、动态记忆或固定双人共享记录。
不使用公共 SAP 机器人或双人 broker 发送邮件摘要。

模型每次用新线程、只读工作目录、禁用 shell、MCP、Apps、插件和网页搜索，
环境不继承邮箱授权码/微信 token。只收到当前邮件及本次拟稿意思。
模型只能返回结构化摘要或正文；接收者、账户、确认状态由外层代码决定。
SDK/Codex 本身会产生本机模型会话记录；实际邮件送到选用模型提供方处理，
本项目没有承诺零云端传输或模型服务零留存。

模型提供方可切换为 DeepSeek API：此时不启动本机 Codex 线程，改为直连
chat completions（JSON 模式）生成同样的结构化摘要/草稿，外层校验与确认
流程不变；邮件内容改送 DeepSeek 处理，本地不产生模型会话记录。

## 当前部署状态

独立项目在功能分支；微信接入也是独立功能分支，必须完成现役门禁后再部署。
不创建新微信 poller、不动公共服务。用户授权后使用邮件项目自己的 LaunchAgent 启动监听及私人网页。
真实上线验收：每种启用邮箱重新触发新邮件，看到对应微信摘要、拟稿、本人
确认和正确账户发信；重复确认不能产生第二封。合成测试不能替代这一步。
